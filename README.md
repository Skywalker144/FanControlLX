# FanControlLX

运行在 Linux 本机的风扇控制后台服务，WebUI 用于查看和修改设置。控制循环独立于浏览器和 SSH 终端。使用 Python 标准库和原生 HTML/CSS/JavaScript，无需 npm、pip、桌面环境或外部 CDN。

## 在另一台 Ubuntu 电脑使用

需要 Python 3.10+。首次上传到 GitHub 后，在目标电脑执行：

```bash
git clone https://github.com/Skywalker144/FanControlLX.git
cd FanControlLX
./webui.sh --diagnose
./webui.sh
```

打开 <http://127.0.0.1:8090>，首次启动用于监控和编辑。真实调速取决于目标主板是否提供可用的 PWM 驱动；另一台电脑需要重新识别风扇和绑定通道。当前后台安装器专用于本机已经签名的 NCT6687 驱动，不能直接用于任意主板。按 [Ubuntu 新机器安装指南](docs/UBUNTU.md) 检测并接入，再安装后台服务。

## 后台运行与开机自启

先在旧的前台服务终端按 Ctrl+C，再执行一次：

```bash
cd /home/sky/RL/FanControlLX
sudo ./install-service.sh --enable-confirmed
```

安装脚本会备份现有配置，将已签名驱动安装到**当前内核**的模块目录，注册并启用 `fancontrollx.service`。`--enable-confirmed` 为当前已确认并绑定的设备启用后台持续控制；未确认通道不会被接管。现有名称、曲线和温度设置保留。

安装后，后台会独立运行并在开机时加载驱动、恢复控制。关闭网页、退出终端或断开 SSH 都不会停止它。网页保存设置会应用到后台，调整曲线时不会重新接管其他已经控制的通道。

```bash
./webui.sh                              # 显示 WebUI 地址后退出，不启动第二个控制进程
systemctl status fancontrollx --no-pager # 查看后台状态
sudo journalctl -u fancontrollx -f       # 查看日志；退出日志不停止后台
sudo systemctl stop fancontrollx        # 停止后台并恢复接管前状态
sudo systemctl start fancontrollx       # 重新启动并恢复已保存策略
sudo systemctl disable --now fancontrollx # 停止并取消开机自启
```

每路设置中的“由后台持续控制”决定保存后是否控制及下次启动是否恢复。卡片的“停止后台控制”和“释放全部控制”会持久保存停用状态；单纯停止整个 systemd 服务不会清除此设置。

可先预览安装计划：`./install-service.sh --dry-run --enable-confirmed`。安装、配置和限制详见 [docs/BACKGROUND.md](docs/BACKGROUND.md)。

## 临时前台运行（调试）

需要 Linux、Python 3.10 或更新版本。在项目目录执行：

```bash
./webui.sh --foreground
```

打开 <http://127.0.0.1:8090>。临时前台模式默认只监控、编辑和保存，不恢复自动控制；退出启动终端可能停止它。已安装后台时，普通 `./webui.sh` 只连接现有服务。

自定义端口：

```bash
./webui.sh --port 8092
```

如果提示已有实例，先在原服务终端按 Ctrl+C；不要同时启动多个控制实例。

## 远程访问

在你自己的电脑上建立 SSH 转发，保持此终端运行：

```bash
ssh -N -L 8090:127.0.0.1:8090 sky@sky-5080
```

将 `sky-5080` 换成平时 SSH 使用的主机名或 IP。然后用你自己电脑的浏览器打开 <http://127.0.0.1:8090>。VS Code Remote SSH 的端口转发也可以。

服务只支持回环 IP，不监听 `0.0.0.0`；浏览器通过 SSH 使用本机接口。无需开放防火墙端口。

## 发现、识别并命名风扇

启动时扫描真实硬件，不再提供预置的两个占位风扇。已知驱动提供对应测速信号且 RPM 大于零的通道会自动加入列表，并绑定 PWM 和测速通道；扫描不会接管风扇。

1. 在“发现并识别风扇”中选择设备，点击“识别并命名”。
2. 点击“开到 100% 辨认”，观察实际哪颗风扇加速。也可使用 50–100% 滑块；测试期间松开滑块即应用。
3. 选择实际设备类型，输入如“前置进风”“后置排风”的名称，点击“确认身份并保存名称”。确认名称会结束测试并恢复原状态，不会自动启用曲线。
4. 点击“编辑曲线”，配置温度响应，保存后再手动启用。

识别测试一次仅一路，15 秒无操作后由后台自动结束并恢复；关闭识别窗口或停止服务也会恢复。临时识别输出不写入温度曲线配置。Pump 接口在确认实际接入的是普通风扇前，只允许 100% 识别测试；确认是水泵的设备使用固定 100% 作为初始配置。

零转速或尚未配对测速的通道放在“其他待确认通道”中，仍可手动识别并命名，不能仅凭 0 RPM 判断未接线。已确认的设备即使后来变成 0 RPM，也会保留在主设备列表。

检测单位是独立控制通道。分线器/集线器下的多颗风扇可能共用一路 PWM 和一个测速信号，无法逐颗独立识别或调速。NCT6687 的同编号 PWM/RPM 配对来自该驱动的明确接口约定，其他未确认映射的驱动仍需手动选择测速通道。

重新扫描会保留已有名称和曲线，也不会重复加入同一通道。设备名称、类型和确认状态会持久化保存；旧版未经修改的两个占位配置会移除，已有自定义配置会保留。

## 绘制曲线

1. 选择左侧已发现的风扇。没有硬件时，也可点击“添加离线配置”先编辑曲线。
2. 拖动节点，或者在曲线下直接输入温度和输出百分比。双击空白位置添加节点，右键删除；至少保留两个节点。节点也支持键盘方向键微调、Shift 加速和 Delete 删除。
3. 选择 CPU、GPU、CPU/GPU 最高温度，或者组合多个温度源。
4. 调整最低/最高输出、回差、响应时间、时间平均和升降速限制。
5. 后台模式勾选“由后台持续控制”，点击“保存并应用”，或 Ctrl+S / Command+S。临时前台模式保存后仍需手动启用。

节点之间线性插值，曲线范围以外保持首尾节点输出。纵轴是风扇控制百分比，不是精确 RPM。RPM 从你绑定的测速通道读取。当前版本没有自动校准或 RPM 闭环控制。

每个风扇都有自己的曲线、温度源和控制参数。提供安静、均衡、性能和固定 50% 预设，以及 JSON 导入/导出。默认保存到 `data/config.json`，原子写入；导出的文件也包含未保存修改。

风扇列表来自硬件扫描；无 PWM 通道时不会虚构物理设备。手动添加的离线配置没有绑定硬件时，目标输出只是计算结果。只有确认过设备身份后才能启用曲线；改变 PWM 绑定后需要重新确认身份。

## 硬件调速

正常使用安装的后台服务即可，不需要保持终端在线。只有临时前台调试时，先停止其他控制实例，再执行：

```bash
sudo ./webui.sh --foreground --control
```

在页面先识别并命名设备。NCT6687 的已检测风扇已自动绑定对应 PWM 和测速通道；其他驱动或离线配置需手动选择通道。配置曲线并保存，再点击该风扇卡片的“启用控制”。启用时先以 100% 接管，再按配置逐步降低输出。不要把水泵当成普通机箱风扇绑定。

- 临时前台模式没有 `--control` 时不允许写入硬件；后台服务按保存的逐路策略控制。
- 后台模式保存/导入后应用其中的持续控制策略。临时前台模式保存会释放已接管风扇，需重新启用。
- “释放控制”恢复接管前的 PWM 和控制模式；接管前是手动模式时，恢复的也会是手动模式。
- 正常停止会尝试恢复。后台重启会恢复勾选的设备，临时前台重启不自动接管。
- 网页关闭、SSH 转发断开不会停止后台。安装后的主进程由 systemd 托管，不依赖终端。
- 自动检测到 `coolercontrold`、`fancontrol`、`fan2go` 或 `thinkfan` 进程时，硬件控制模式会拒绝启动，避免争用通道。
- PWM 与测速通道请按实际主板接线绑定，不假设 `pwm1` 一定对应 `fan1_input`。分线器一般只有一个测速信号。

故障处理：温度源缺失、任一所选原始温度达到保护阈值时，立即跳过时间平均、回差和限速，输出 100%。绑定测速后，接管超过 10 秒仍没有 RPM，也输出 100%。此版本最低输出为 20%，不支持自动停转。

NCT6687 驱动若暴露 `fan_control_watchdog`，每次调速都会续期 15 秒硬件租约。进程被强制终止后，驱动超时恢复自身保存的曲线。其他没有此接口的驱动，在 SIGKILL、内核故障等情况下无法由应用保证自动恢复。

目前仅为明确采用标准手动/自动模式的 NCT6687 和部分 NCT677x/NCT679x 驱动开放控制。其他芯片显示为只读。当前版本不控制显卡风扇，也不读写未验证的 EC 寄存器。

## 本机已确认的限制

主机 `sky-5080`，微星 MAG B860M MORTAR WIFI (MS-7E40)，NCT6687D 芯片。CPU 和 RTX 5080 温度可读取。

已完成模块签名及 MOK 证书登记，社区 `nct6687` 驱动已成功加载，暴露 8 个 PWM 通道和硬件看门狗接口。普通用户诊断显示通道不可写属于预期权限限制；安装的后台服务以所需权限控制硬件。

已识别并保存三个实际风扇：CPU Fan（pwm1）、CaseOut（pwm2，驱动标签为 Pump Fan）、CaseIn（pwm6）。2026-10-18 检查确认后台服务正在运行、开机自启已启用，三路均按保存的曲线持续控制，实际 PWM 回读与计算输出一致，测速正常。其余通道为 0 RPM，不能据此认定风扇故障，也不能假设每个暴露通道都有实际接线。此次检查未执行重启或异常退出测试。

后台安装脚本会注册当前内核的已签名驱动并在服务启动前自动加载。尚未配置 DKMS，**更新内核后需要重新编译、签名并运行安装脚本**；同一受信任签名密钥无需重复登记证书。若驱动无法加载，服务不会盲目接管风扇。

更多硬件调查结果与模块来源见 [docs/HARDWARE.md](docs/HARDWARE.md)。Web 应用本身不需要内核签名。

## 演示和诊断

```bash
# 使用模拟传感器和模拟风扇，绝不写入真实硬件
./webui.sh --demo --port 8091

# 打印本机硬件信息，不启动服务、不修改硬件
./webui.sh --diagnose

# 指定独立配置目录
./webui.sh --data-dir /path/to/data
```

演示配置保存为 `data/config.demo.json`，与真实配置完全分开。
