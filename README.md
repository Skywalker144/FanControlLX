# FanControlLX

Linux 本机风扇控制服务与 WebUI。使用 Rust 后台及原生 HTML/CSS/JavaScript，网页资源嵌入可执行文件。后台独立采样和调速，关闭网页或断开 SSH 不影响运行，无需 npm、pip、桌面环境或外部 CDN。运行与安装均无需 Python；部分测试工具使用 Python。

## 运行方式

- 启动时发现设备；编辑页可见时每 30 秒刷新设备目录、名称与能力。健康后台和观看页不做周期性发现；异常读数立即进入保护，故障发现按 30 秒间隔重试。实时温度、测速与保护仍约每秒处理。
- NVIDIA 由独立进程持有逐路 10 秒租约，并检查显卡自身温度。
- 主板输出变化时立即写入，稳定时每 3 秒重新写入；芯片看门狗独立每 3 秒续期，保留 15 秒超时保护。
- 网页隐藏时停止轮询，恢复可见时立即刷新；只更新当前标签页，配置按版本获取、历史增量传输。`/api/state` 支持完整响应。
- 控制后台、安装器及恢复钩子均为 Rust；支持读取 v1/v2 配置。

首次从 Python 服务升级：

```bash
git pull --ff-only
./build.sh
sudo ./install-service.sh   # 沿用其他系统驱动的机器加 --skip-driver
```

构建需要 Rust 1.82+ 和 C 链接器；安装 Rust 可参考 [官方安装说明](https://www.rust-lang.org/tools/install)。构建完成后运行不需要 Rust 工具链。首次迁移必须更新服务单元，之后代码或网页更新需重新构建再重启。架构和迁移说明见 [Rust 后台](docs/RUST.md)。

## 更新与配置兼容

每台机器使用自己的 `data/config.json`；演示模式使用 `data/config.demo.json`。`data/` 已被 Git 忽略，正常 `git pull` 不会覆盖本机的曲线、名称、通道绑定或控制开关。

0.4 兼容读取旧版 v1 配置，保留每颗风扇的曲线节点、温度源、设备身份、PWM/测速绑定、平滑参数和持续控制状态。读取时只在内存中补齐 v2 字段；首次保存时，先把原版完整备份到 `data/config.before-v2.json`，再原子写入新版配置。此备份不会被后续保存覆盖。演示配置对应的备份为 `config.demo.before-v2.json`。

旧曲线保留为每颗风扇的“独立曲线”，不会自动合并或更改温度源。共享曲线保存在同一 JSON 的 `curves` 中，风扇通过 `curve_id` 引用；温度源仍属于风扇。新版格式不能交给旧版程序编辑，回退程序前应停止服务并恢复备份。

已安装后台服务的机器更新后执行：

```bash
git pull
./build.sh
sudo systemctl restart fancontrollx
```

随后刷新网页。本机和其他机器分别保留各自的配置，不需要相互复制配置、驱动或硬件绑定。代码更新无需重新安装驱动；内核更新仍需按硬件文档重新编译、签名并安装模块。临时前台模式请退出旧进程后重新启动。网页检测到旧后端时会提示重启并禁用配置写入。

前端组件、依赖和交互约定见 [前端说明](docs/FRONTEND.md)。后台架构、驱动访问和接口说明见 [Rust 后台](docs/RUST.md)。

## 日常操作

打开 <http://127.0.0.1:8090> 默认进入只读观看页，显示每个风扇的运行状态、输入温度、RPM 和输出。点击“编辑风扇”进入 <http://127.0.0.1:8090/edit>，使用原有控制台；编辑页顶部的“进入观看页”按钮可随时返回观看页，手机端同样可见。两页共用一个后台，关闭网页不停止控制。观看页不加载编辑器或触发设备发现，隐藏时停止轮询。

观看/编辑是操作界面区分，不是账号权限隔离；本机用户仍可主动进入编辑页。服务继续只监听回环地址。

编辑页的功能如下：

- **卡片排序**：拖动卡片左上角的风扇图标调整顺序，手机同样支持。顺序自动保存，刷新后保持；也可聚焦该图标并按 Alt + 方向键前后移动。
- **温度源**：直接选择 CPU、GPU、CPU/GPU 取最高温度；也可在设置中组合原始温度源。用户自由决定每颗风扇用什么温度，不根据名称、位置或接口推断散热对象。
- **温度曲线**：曲线与手动保留分段切换外观，和温度源等宽排列在同一行。曲线一侧支持下拉选择独立/共享曲线，从手动模式选择曲线后立即切换。温度源和曲线可以自由搭配。
- **手动调速**：点击卡片中的“手动”，滑块松开即保存。输出遵守这颗风扇的最低/最高输出及升降速限制；异常温度或测速仍触发 100% 保护。
- **启用控制**：开关与运行状态合并在卡片右上角。正常接管从 50% 起步（遵守输出范围），再按曲线和平滑设置调整。后台模式下开关立即保存，启用的设备在服务重启后恢复。关闭开关或“停止全部控制”会恢复接管前的硬件状态，并持久保存停用策略。临时前台模式的开关仅本次运行有效，不自动恢复控制。
- **编辑曲线**：点击卡片中的曲线缩略图打开编辑器，选择预设、拖动节点、单击空白添加、右键删除，也支持数字输入、方向键、Shift 加速和 Delete 删除。节点列表独立滚动，图表与保存按钮保持可见，至少保留两个节点。新建曲线默认三个节点：30°C → 20%、50°C → 50%、80°C → 100%。预览不调速；“应用并保存”后生效，“取消”放弃修改。Ctrl+S / Command+S 提交当前编辑器。
- **曲线库**：新建、复制、改名、编辑、删除共享曲线；编辑时会显示引用它的风扇。正在被引用的曲线不能直接删除。独立曲线可在编辑时勾选“保存为共享曲线”，保存并分配一步完成。
- **设置**：名称、PWM/测速绑定、最低/最高输出、回差、响应时间、时间平均、保护温度和升降速限制。应用只提交改过的字段，不覆盖其他风扇或其他页面的新设置。

曲线只定义“温度 → 输出百分比”的形状，不绑定 CPU 或 GPU。多颗风扇共用曲线时，仍各自读取选择的温度源，并应用各自的平滑和输出限制。百分比不是精确 RPM；本版不提供自动校准或 RPM 目标控制。新建主板风扇配置最低输出默认为 0%，允许设置 0–100% 的输出范围；主动输出 0% 时不触发停转保护，过热和温度源丢失仍立即保护。NVIDIA 仍遵守驱动输出范围，曲线为 0% 时交回显卡自动模式，是否停转由显卡决定。已有配置中的曲线和输出限制保持原值，可在设置中修改。

正在控制的通道在保存设置、调整曲线时保持控制租约，不重新接管其他风扇。多页面同时编辑同一设置发生冲突时会保留编辑器并提示重新打开，避免旧页面覆盖新设置。

导入/导出位于顶部。导出的是已保存的配置，不包含弹窗中尚未应用的修改。导入兼容旧版格式，并替换本机全部配置、应用其中的后台控制策略。

## 设备设置

首次使用到“设备设置”扫描真实硬件。有测速信号的通道会自动列出，扫描不会接管新设备；0 RPM 通道放在“其他待确认通道”中，不直接认定为空接口或故障。

1. 点击“确认设备”，自行命名，确认接入的是普通风扇还是水泵。无需定义它是为 CPU 还是 GPU 散热。
2. 不确定位置时可用“100% 辨认”及 50–100% 滑块进行临时测试。一次仅测试一路；15 秒无操作、关闭窗口或切离网页会结束测试。
3. 测试结束恢复此前的控制模式，原有持续控制开关不变；如果原来处于曲线或手动控制，会继续运行。正常停止服务仍恢复最初接管前的硬件状态。
4. 返回控制台，自行选择温度源和曲线，然后启用控制。

未确认的 Pump 接口只允许 100% 测试；水泵首次确认使用固定 100% 配置。名称和设备类型可直接确认，不要求一定执行调速测试。改变 PWM 绑定后需要重新确认设备。没有硬件时，可先添加离线配置进行编辑，离线目标不代表实际调速。

检测单位是独立控制通道，分线器/集线器可能共用 PWM 和单个测速信号，不能逐颗控制。NCT6687 的同编号 PWM/RPM 配对使用驱动的明确约定，其他驱动需要按接线手动选择测速通道。

## 安装与后台运行

在另一台 Linux 机器上：

```bash
git clone https://github.com/Skywalker144/FanControlLX.git
cd FanControlLX
./build.sh
./webui.sh --diagnose
./webui.sh
```

首次启动只监控和编辑，真实调速取决于主板驱动。其他机器从 [Ubuntu 安装指南](docs/UBUNTU.md) 开始接入，不复制本机驱动和硬件绑定。

后台安装器默认安装本机已签名的 NCT6687 驱动；NVIDIA 或沿用系统驱动的其他机器加 `--skip-driver`。先停止旧的前台控制进程，再运行：

```bash
sudo ./install-service.sh --enable-confirmed
./webui.sh
```

安装器备份配置、安装当前内核的已签名驱动，注册并启用 systemd 服务。`--enable-confirmed` 只启用已确认并绑定的设备；普通重新安装不改变控制开关。可先通过 `./install-service.sh --dry-run --enable-confirmed` 查看计划。

```bash
systemctl status fancontrollx --no-pager
sudo journalctl -u fancontrollx -f
sudo systemctl restart fancontrollx
sudo systemctl stop fancontrollx
sudo systemctl disable --now fancontrollx
```

停止整个服务会恢复硬件状态，保留逐路控制开关供下次启动恢复。详情见 [后台运行说明](docs/BACKGROUND.md)。

临时前台调试（先停止其他控制实例）：

```bash
./webui.sh --foreground                  # 监控和编辑
sudo ./webui.sh --foreground --control   # 允许逐路手动启用控制
```

临时模式保存设置也会保留正在运行的控制；退出进程会恢复硬件，下次启动不会自动接管。

远程使用 SSH 转发：

```bash
ssh -N -L 8090:127.0.0.1:8090 sky@sky-5080
```

浏览器打开本机 <http://127.0.0.1:8090>。服务仅监听回环 IP，不支持 `0.0.0.0`。

## 硬件与保护

温度源缺失、任一所选原始温度超过保护阈值，或已绑定测速的风扇接管超过 10 秒仍无 RPM，立即输出 100%，跳过平均、回差和限速。NCT6687 驱动提供 15 秒硬件看门狗；其他驱动的异常退出恢复能力取决于硬件接口。

控制支持已验证模式的 NCT6687、部分 NCT677x/NCT679x 主板驱动，以及提供完整 NVML 接口的 NVIDIA 显卡。其他芯片只读，不读写未验证的 EC 寄存器。检测到 `coolercontrold`、`fancontrol`、`fan2go`、`thinkfan` 时拒绝启动另一硬件控制进程。

## NVIDIA 显卡风扇（0.5.1）

Ubuntu 安装正常工作的 NVIDIA 驱动后，显卡风扇会自动出现在设备设置和控制台；自动停转的 0 RPM 设备也会列出。无需安装 pip 包、CUDA Toolkit 或配置 Coolbits。每路按 GPU UUID 和风扇索引绑定，默认未确认、未接管。确认设备后可使用原有曲线、共享曲线、手动调速和后台控制。

显卡新配置默认跟随其自身温度，用户可以更换温度源。0.5.1 起，曲线计算输出恰为 0% 时交回显卡自动模式，保持控制开关和租约；是否停转由显卡自身条件决定。曲线恢复正值时自动接管，遵守配置和驱动报告的最低输出（本机 RTX 5080 的驱动范围为 30–100%）。手动滑块仍使用有效运行范围，不直接强制停转。温度平均和回差继续生效；0% 的模式切换跳过输出降速平滑，避免被最低输出卡住。

显卡自身达到 85°C、达到用户设置的更低保护温度，或自身温度不可用时，即使曲线为 0% 也立即接管并使用最大输出。关闭控制恢复接管前模式：原为自动则恢复显卡自动调速，原为手动则恢复原目标百分比。

显卡由独立进程持有控制租约，每路超过 10 秒未收到有效调速请求、父进程退出或收到 SIGTERM 时尝试恢复。恢复记录写在 `data/nvidia-leases.json`；新服务还包含停止后的恢复钩子，并在下一次显卡接管前处理残留记录。软件守护无法替代硬件看门狗，整个进程组被强杀时依赖 systemd 恢复钩子或下次启动恢复。NVML 的百分比/RPM 是驱动报告的工作值，不作为风扇实际旋转的证明，也不触发现有主板测速故障保护。

本机升级需更新服务配置，保留已有开关：

```bash
sudo ./install-service.sh
```

从 0.5.x 升级到 0.6 时先运行 `./build.sh`，再运行安装器，将主服务和恢复钩子切换为 Rust；已有曲线和逐路开关保留。

另一台机器若沿用已有系统驱动，可使用 `sudo ./install-service.sh --skip-driver`，不安装或加载本机的 NCT6687 模块。详细安装、验证与恢复说明见 [NVIDIA 接入说明](docs/NVIDIA.md)。

本机 MAG B860M MORTAR WIFI / NCT6687D 已接入 CPUFan、CaseOut、CaseIn 三路，CPU 和 RTX 5080 温度可读取。已完成模块签名及 MOK 登记，尚未配置 DKMS；内核升级后需要重新构建、签名并运行安装器。记录见 [硬件接入说明](docs/HARDWARE.md)。

python3 -m unittest discover -s tests -v
cargo test --locked

自动测试使用模拟硬件、临时目录和本机测试套接字，覆盖保护、租约恢复、共享曲线、局部保存、并发冲突、v1 升级及备份、重启持久化和 HTTP 校验，见 [测试说明](docs/TESTING.md)。

./target/release/fancontrollx --service --demo --port 18091 --data-dir /tmp/fancontrollx-browser-test
# 另一终端执行；测试会重置该演示实例的模拟配置
