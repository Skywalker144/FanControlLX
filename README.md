# FanControlLX

Linux 本机风扇控制服务与 WebUI。后台独立采样和调速，关闭网页或断开 SSH 不影响运行。Python 3.10+、原生 HTML/CSS/JavaScript，无需 npm、pip、桌面环境或外部 CDN。

## 更新与配置兼容

每台机器使用自己的 `data/config.json`；演示模式使用 `data/config.demo.json`。`data/` 已被 Git 忽略，正常 `git pull` 不会覆盖本机的曲线、名称、通道绑定或控制开关。

0.4 兼容读取旧版 v1 配置，保留每颗风扇的曲线节点、温度源、设备身份、PWM/测速绑定、平滑参数和持续控制状态。读取时只在内存中补齐 v2 字段；首次保存时，先把原版完整备份到 `data/config.before-v2.json`，再原子写入新版配置。此备份不会被后续保存覆盖。演示配置对应的备份为 `config.demo.before-v2.json`。

旧曲线保留为每颗风扇的“独立曲线”，不会自动合并或更改温度源。共享曲线保存在同一 JSON 的 `curves` 中，风扇通过 `curve_id` 引用；温度源仍属于风扇。新版格式不能交给旧版程序编辑，回退程序前应停止服务并恢复备份。

已安装后台服务的机器更新后执行：

```bash
git pull
sudo systemctl restart fancontrollx
```

随后刷新网页。本机和其他机器分别保留各自的配置，不需要相互复制配置、驱动或硬件绑定。代码更新无需重新安装驱动；内核更新仍需按硬件文档重新编译、签名并安装模块。临时前台模式请退出旧进程后重新启动。网页检测到旧后端时会提示重启并禁用配置写入。

## 日常操作

打开 <http://127.0.0.1:8090>，风扇控制台以卡片显示硬件输出、RPM、输入温度、运行状态和控制开关。

- **温度源**：直接选择 CPU、GPU、CPU/GPU 取最高温度；也可在设置中组合原始温度源。用户自由决定每颗风扇用什么温度，不根据名称、位置或接口推断散热对象。
- **温度曲线**：选择此风扇的独立曲线，或曲线库中的共享曲线。温度源和曲线可以自由搭配。
- **手动调速**：点击“手动调速”，滑块松开即保存。输出遵守这颗风扇的最低/最高输出及升降速限制；异常温度或测速仍触发 100% 保护。
- **启用控制**：后台模式下开关立即保存，启用的设备在服务重启后恢复。关闭开关或“停止全部控制”会恢复接管前的硬件状态，并持久保存停用策略。临时前台模式的开关仅本次运行有效，不自动恢复控制。
- **编辑曲线**：打开编辑器，选择预设、拖动节点、单击空白添加、右键删除，也支持数字输入、方向键、Shift 加速和 Delete 删除。至少保留两个节点。预览不调速；“应用并保存”后生效，“取消”放弃修改。Ctrl+S / Command+S 提交当前编辑器。
- **曲线库**：新建、复制、改名、编辑、删除共享曲线；编辑时会显示引用它的风扇。正在被引用的曲线不能直接删除。独立曲线可在编辑时勾选“保存为共享曲线”，保存并分配一步完成。
- **设置**：名称、PWM/测速绑定、最低/最高输出、回差、响应时间、时间平均、保护温度和升降速限制。应用只提交改过的字段，不覆盖其他风扇或其他页面的新设置。

曲线只定义“温度 → 输出百分比”的形状，不绑定 CPU 或 GPU。多颗风扇共用曲线时，仍各自读取选择的温度源，并应用各自的平滑和输出限制。百分比不是精确 RPM；本版不提供自动校准、RPM 目标控制或自动停转，最低输出为 20%。

正在控制的通道在保存设置、调整曲线时保持控制租约，不重新接管其他风扇。多页面同时编辑同一设置发生冲突时会保留编辑器并提示重新打开，避免旧页面覆盖新设置。

导入/导出位于顶部。导出的是已保存的配置，不包含弹窗中尚未应用的修改。导入兼容旧版格式，并替换本机全部配置、应用其中的后台控制策略。

## 设备设置

首次使用到“设备设置”扫描真实硬件。有测速信号的通道会自动列出，扫描不会接管新设备；0 RPM 通道放在“其他待确认通道”中，不直接认定为空接口或故障。

1. 点击“确认设备”，自行命名，确认接入的是普通风扇还是水泵。无需定义它是为 CPU 还是 GPU 散热。
2. 不确定位置时可用“100% 辨认”及 50–100% 滑块进行临时测试。一次仅测试一路；15 秒无操作、关闭窗口或切离网页会结束测试。
3. 测试结束恢复此前的控制模式，原有持续控制开关不变；如果原来处于曲线或手动控制，会继续运行。正常停止服务仍恢复最初接管前的硬件状态。
4. 返回控制台，自行选择温度源和曲线，然后启用控制。

未确认的 Pump 接口只允许 100% 测试；水泵首次确认使用固定 100% 配置。名称和设备类型可直接确认，不要求一定执行调速测试。改变 PWM 绑定后需要重新确认设备。没有硬件时，可先添加离线配置进行编辑，离线目标不代表实际调速。

检测单位是独立控制通道，分线器/集线器可能共用 PWM 和单个测速信号，不能逐颗控制。NCT6687 的同编号 PWM/RPM 配对使用驱动的明确约定，其他驱动需要按接线手动选择测速通道。

## 安装与后台运行

在另一台 Linux 机器上：

```bash
git clone https://github.com/Skywalker144/FanControlLX.git
cd FanControlLX
./webui.sh --diagnose
./webui.sh
```

首次启动只监控和编辑，真实调速取决于主板驱动。其他机器从 [Ubuntu 安装指南](docs/UBUNTU.md) 开始接入，不复制本机驱动和硬件绑定。

当前后台安装器专用于本机已签名的 NCT6687 驱动。先停止旧的前台控制进程，再运行：

```bash
sudo ./install-service.sh --enable-confirmed
./webui.sh
```

安装器备份配置、安装当前内核的已签名驱动，注册并启用 systemd 服务。`--enable-confirmed` 只启用已确认并绑定的设备；普通重新安装不改变控制开关。可先通过 `./install-service.sh --dry-run --enable-confirmed` 查看计划。

```bash
systemctl status fancontrollx --no-pager
sudo journalctl -u fancontrollx -f
sudo systemctl restart fancontrollx
sudo systemctl stop fancontrollx
sudo systemctl disable --now fancontrollx
```

停止整个服务会恢复硬件状态，保留逐路控制开关供下次启动恢复。详情见 [后台运行说明](docs/BACKGROUND.md)。

临时前台调试（先停止其他控制实例）：

```bash
./webui.sh --foreground                  # 监控和编辑
sudo ./webui.sh --foreground --control   # 允许逐路手动启用控制
```

临时模式保存设置也会保留正在运行的控制；退出进程会恢复硬件，下次启动不会自动接管。

远程使用 SSH 转发：

```bash
ssh -N -L 8090:127.0.0.1:8090 sky@sky-5080
```

浏览器打开本机 <http://127.0.0.1:8090>。服务仅监听回环 IP，不支持 `0.0.0.0`。

## 硬件与保护

温度源缺失、任一所选原始温度超过保护阈值，或已绑定测速的风扇接管超过 10 秒仍无 RPM，立即输出 100%，跳过平均、回差和限速。NCT6687 驱动提供 15 秒硬件看门狗；其他驱动的异常退出恢复能力取决于硬件接口。

控制仅开放给已验证控制模式的 NCT6687 及部分 NCT677x/NCT679x 驱动；其他芯片只读。当前不控制显卡风扇，不读写未验证的 EC 寄存器。检测到 `coolercontrold`、`fancontrol`、`fan2go`、`thinkfan` 时拒绝启动另一硬件控制进程。

本机 MAG B860M MORTAR WIFI / NCT6687D 已接入 CPUFan、CaseOut、CaseIn 三路，CPU 和 RTX 5080 温度可读取。已完成模块签名及 MOK 登记，尚未配置 DKMS；内核升级后需要重新构建、签名并运行安装器。记录见 [硬件接入说明](docs/HARDWARE.md)。

## 演示与验证

```bash
./webui.sh --demo --port 8091
./webui.sh --diagnose
./webui.sh --data-dir /path/to/data
python3 -m unittest discover -s tests -v
node --check static/app.js
bash -n webui.sh
```

自动测试使用模拟硬件、临时目录和本机测试套接字，覆盖保护、租约恢复、共享曲线、局部保存、并发冲突、v1 升级及备份、重启持久化和 HTTP 校验。

可选浏览器测试（Node 22+，使用已有 Chromium，不安装依赖）：

```bash
# 用独立临时配置启动后台行为的演示服务
python3 -m fancontrollx.daemon --demo --port 18091 --data-dir /tmp/fancontrollx-browser-test
# 另一终端执行；测试会重置该演示实例的模拟配置
CHROME_BIN=/path/to/chrome node tests/browser-smoke.mjs http://127.0.0.1:18091
```

测试拒绝操作真实硬件实例，验证命名、识别/恢复、不同温度源共享曲线、拖拽、取消/应用、滑块、开关、设置、离线配置、曲线复制/删除、并发冲突、刷新持久化和桌面/手机布局。截图保存到 `test-results/`。可对现有真实实例添加 `--snapshot-only` 做只读截图。
