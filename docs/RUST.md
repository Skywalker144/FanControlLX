# Rust 后台（0.6）

控制服务和独立 NVIDIA 写入进程均由 `target/release/fancontrollx` 提供。HTTP 服务仅监听回环地址，使用两个固定请求线程和有界队列。主线程独占控制器及硬件，HTTP 线程通过有界命令队列取状态或提交修改；控制截止时间在每条命令前检查。请求体读取、JSON 序列化和网络发送均不占用控制线程。网页资源编译进可执行文件。

## 模块

| 模块 | 职责 |
|---|---|
| `src/config.rs` | v1/v2 配置校验、首次迁移备份、原子保存 |
| `src/engine.rs` | 曲线、平滑、保护、识别测试、控制策略及网页操作 |
| `src/hardware.rs` | hwmon 发现缓存与实时采样、主板控制、NVML 读数 |
| `src/nvml.rs` | 动态加载可选的 NVIDIA 驱动库，封装 C ABI |
| `src/writer.rs` | 独立 NVIDIA 写入进程、逐通道租约和恢复记录 |
| `src/telemetry.rs` | 可复用的设备索引、每轮温度分组及完整性检查 |
| `src/runtime.rs` | 控制器单一所有者、有界命令、按需快照共享、请求过期与原子状态版本 |
| `src/state.rs` | 不可变读取快照、直接序列化、观看/编辑响应及增量协议 |
| `src/server.rs` | 本地 HTTP、Host/Origin/CSRF 检查、状态响应缓存与静态资源校验 |

代码使用标准库线程和套接字；依赖锁定在 `Cargo.lock`。没有 NVIDIA 驱动时主板仍可运行。只有 NVML 无法提供 GPU 温度时才尝试 `nvidia-smi`，成功采样间隔 3 秒，失败退避 30 秒，子进程超时 2 秒。

## 采样和写入

启动时发现设备，手动扫描会立即刷新。可见编辑页每 5 秒左右发送心跳，后台持有 15 秒编辑租约，仅在租约有效时每 30 秒刷新拓扑。观看页及正常无网页后台不做周期性拓扑发现。读数失效使缓存失效，按 30 秒间隔重试发现；已配置通道缺失也会触发恢复发现，因而设备重连不依赖编辑页。失效读数立即用于保护判断，不会用旧温度填充。NVML 范围最多缓存 60 秒，重新发现设备时清空。句柄和预先解析的驱动函数指针只在其所属 NVML 实例生命周期内使用。NVML 可选接口缺失仍允许只读监控；读数失败立即标记通道不可写，保持发现时间戳，以免绕过 30 秒重试间隔。

手动扫描读取一次硬件样本，在写入配置之前先应用保护；配置新增后的输出计算使用同一份样本。温度、测速、实时模式和实际输出仍约每秒读取。过热和所选温度源缺失继续绕过曲线平滑、回差、响应时间和用户输出上限。

主板输出变化立即写入；不变时每 3 秒重新写入。看门狗独立按芯片每 3 秒续期，不能因输出稳定而停止续期。NVIDIA 每轮继续发送有效控制请求，写入进程独立检查自身温度并更新 10 秒租约；不能以缓存替代安全检查。

hwmon 数值读取使用有界栈缓冲区，每次重新打开文件并读取到 EOF；无效、过长、已移除设备仍返回缺失读数。180 条温度历史以数值结构保存，由 HTTP 线程直接序列化。最后一路 NVIDIA 租约成功恢复后关闭写入进程连接并回收子进程，下次接管时重新启动；恢复失败或仍有租约时继续保留守护。

控制参数、曲线节点、温度源选择与聚合方式在配置变更时预解析；每轮使用解析结果进行数值插值。设备索引在 ID 或顺序变化时重建，常规采样复用；CPU/GPU 组温度每轮各计算一次，组内任一缺失读数仍立即触发保护。控制结果保存为数值结构，由 HTTP 线程直接序列化。`Hardware::sample_into` 允许复用采样存储：hwmon 发现版本不变时只更新数值和读数状态；发现变化时重建布局。NVML 的温度、芯片、风扇与通道对象也按独立发现版本复用，正常采样只覆盖读数和可写状态；持久的权限诊断复用字符串。设备消失或 NVML 重连失败时清除旧布局，读数恢复后还原原来的权限限制。复用的是存储，所有读数仍每轮重新读取。

HTTP 读取使用按需生成的不可变快照。同一控制版本的不同查询共享快照，配置通过 `Arc<Value>` 与控制器共享，只有配置修改才创建新版本。观看请求仅复制输出、等待状态和最多 80 条数值历史；只有编辑请求才补齐硬件元数据、日志和识别状态。生成快照之后，字段选择、发现信息拼装与 JSON 编码都在 HTTP 工作线程执行。控制线程保留一个当前快照槽位，采样、配置操作与停止时清空；已经在编码的请求可以完成，不阻止下一轮采样。无人读取时不创建快照。

HTTP 状态缓存在采样、配置操作开始与完成时失效，服务停止时也立即失效，防止驱动阻塞期间反复返回旧读数；至多保留两份响应体、合计 256 KiB；无访问时不主动生成状态响应。健康状态使用原子布尔值。请求过期后不会开始执行排队的修改；已经开始执行的操作不能通过客户端超时撤销，超时后应先刷新状态。静态 HTML、CSS、JS、SVG 使用内容哈希 ETag 和 `no-cache` 重验证，未修改时返回 304；状态与错误响应继续 `no-store`。

温度平滑维护滑动总和，样本进入/过期时增减；温度源、聚合方式或平滑时间改变时同时清空样本与总和。原始温度保护仍优先于平滑。状态接口借用不可变快照直接序列化输出、历史、发现与观看卡片。HTTP 按有界行块读取请求头，每个工作线程复用请求头缓冲区，字段借用缓冲区；保留 16 KiB 限制、大小写不敏感的重复头检查、CSRF 和请求体校验。

网页不可见时暂停轮询，恢复可见时立即取状态。后台控制与网页连接无关。只刷新可见标签页；`/api/state?since=<config_revision>&after=<timestamp>` 可省略未变的配置并返回增量历史，原 `/api/state` 保持完整响应。

默认 `/`（也可用 `/view`）为观看页，使用只读 `/api/view` 返回实时状态、曲线显示信息和最近 80 条温度历史，不发送完整配置、CSRF 令牌、设备发现或日志。`/edit` 为编辑工作台。两页共用同一后台和端口，不额外创建控制进程。编辑心跳必须通过原有 CSRF 校验；观看请求不延长发现租约。编辑页隐藏、关闭或崩溃后停止发送心跳，后台的发现租约在最后一次收到心跳的 15 秒后失效。观看页用于查看状态，编辑页提供配置操作；两页不做用户权限隔离，本机用户均可打开。

观看页后续请求使用 `/api/view?since=<view_revision>&after=<history_cursor>`。`view_revision` 包含启动随机标识与配置版本；相同时 `fans_delta=true`，每路只返回 ID、输出和等待状态。`after` 为采样序号，与系统时钟无关；缺失、越界、超过 80 条历史窗口或版本不匹配时返回完整历史，否则 `history_delta=true`，只返回新增样本。客户端按请求开始时的快照合并，保留至多 80 条历史。重启、更名、排序、曲线调整和导入会自动补发完整显示信息；不带参数的原接口继续返回完整响应。

## 构建和升级

需要 Rust 1.82+ 和系统 C 链接器。使用 `./build.sh`（等价于 `cargo build --release --locked`）。构建结果可在兼容的 Linux 系统运行；仍需要该系统的硬件驱动及 NVIDIA 驱动库（若使用显卡）。

首次从 Python 服务升级：

```bash
./build.sh
sudo ./install-service.sh
```

沿用系统驱动的其他机器使用 `--skip-driver`。安装器在停止旧服务之前验证可执行文件及驱动，备份原服务单元和配置，保留原控制开关。安装器由同一 Rust 二进制的 `--install-service` 子命令提供，不常驻；Shell 入口只定位项目目录并转交参数。

随后每次更新：

```bash
git pull --ff-only
./build.sh
sudo systemctl restart fancontrollx
```

网页资源也需要重新构建，刷新浏览器即可加载新资源。

## 验证

```bash
cargo test --locked
cargo clippy --all-targets --locked -- -D warnings
python3 -m unittest discover -s tests -v
node --check static/app.js
```

`tests/test_rust.py` 在临时目录运行演示服务，并编译 `tests/mock_nvml.c` 为测试用驱动库，验证独立进程的 EOF、SIGTERM、SIGKILL 恢复、超时租约、原手动目标恢复和显卡自身温度保护。不会通过模拟库操作真实显卡。


测试范围和运行条件见 [测试说明](TESTING.md)。
