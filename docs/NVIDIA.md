# NVIDIA 显卡风扇

0.5 通过驱动自带的 `libnvidia-ml.so.1` 接入 NVML。支持实际提供风扇枚举、控制策略查询、手动调速和自动模式恢复接口的 NVIDIA 独立显卡。是否支持以本机驱动探测及实测为准；不以型号列表推断。当前不实现 AMD。

## 已有后台服务

首次升级到 0.5 后执行：

```bash
sudo ./install-service.sh
```

安装器备份配置和原服务单元，更新恢复钩子，重启服务，保留逐路启用开关。普通安装不启用新显卡风扇；无需添加 `--enable-confirmed`。

打开 <http://127.0.0.1:8090>，新显卡通道会出现在控制台和设备设置。逐路确认名称后选择温度源、曲线，再启用控制。可以共享曲线，也可以分别控制驱动暴露的各路；驱动索引与物理扇叶的对应关系需要实机辨认。

## 另一台 Ubuntu 机器

先确认 `nvidia-smi` 正常，再在无其他控制实例运行时启动：

```bash
sudo ./webui.sh --foreground --control
```

在网页确认设备并保存配置，退出前台进程后安装后台服务：

```bash
sudo ./install-service.sh --skip-driver
```

这会沿用已有系统驱动，不安装或加载 NCT6687 模块。无需 CUDA Toolkit、pip 包、X11、桌面会话或 Coolbits；驱动必须提供本机可用的 NVML 接口。主板通道若由其他已安装驱动提供，可与显卡一起使用。

每台机器保留自己的 `data/config.json`。通道 ID 使用 GPU UUID 和风扇索引，不因 GPU 枚举顺序变化而串卡；不要复制另一台机器的硬件绑定。

## 调速和保护

- 自动模式的 0 RPM 设备也会被发现，扫描和确认名称均不调速。
- 新显卡配置默认读取该 GPU 自身温度。曲线来源可以更改，但 GPU 自身温度保护始终保留：达到 85°C 或用户设置的更低阈值、或者温度不可用时，跳过平滑及配置的最高输出限制，使用驱动允许的最大输出。
- 0.5.1 起，曲线计算输出恰为 0% 时调用默认自动策略，保持控制开关开启及原租约，网页显示“显卡自动调速”。显卡此时也可能继续转动，是否停转由自身条件决定，实际百分比和 RPM 仍正常显示。
- 曲线恢复正值时重新接管，按配置和驱动报告的范围限制，本机 RTX 5080 报告 30–100%。手动滑块仍使用有效运行范围，不提供强制停转。主板风扇的曲线 0% 仍遵守原来的最低输出。
- 温度平均、温度回差继续应用；进入自动模式直接切换，不逐步降低百分比。首次在 0% 曲线下启用或重启，不产生额外的 100% 接管脉冲。自动模式下仍持续监测温度，保护触发时立即接管并使用最大输出。
- NVML 百分比和 RPM 是驱动报告的工作值。RPM 查询不支持时显示 `—`，仍可控制；不把缺失或 0 RPM 当作可靠的物理停转故障信号。主板风扇原有测速保护不变。
- 关闭控制、结束识别或正常停服务恢复接管前状态。原为自动时调用默认自动策略恢复接口；原为手动时恢复原目标输出，而非采样到的瞬时输出。
- 接管前原状态无法读取、恢复函数不可用、调速范围不明或权限不足时保持只读，在通道诊断中显示原因。

例如，设置 `[25°C, 0%]`、`[45°C, 0%]`、`[55°C, 50%]`、`[85°C, 100%]`，在曲线计算温度不超过 45°C 时交回自动模式，高于此温度后恢复手动曲线控制。仅把最左侧单个节点设为 0%，其他节点为正值时，中间插值通常仍大于 0%；需要让希望交回自动的温度区间保持 0%。

已经安装 0.5 服务单元的机器，更新代码后执行 `sudo systemctl restart fancontrollx`，刷新网页即可使用新逻辑。配置格式不变，无需重新确认设备或修改最低输出为 0。

## 独立守护和恢复

只有独立写入进程调用 NVML 设置接口。每个通道需要主控制循环续约；10 秒未收到有效写入、父进程连接关闭或写入进程收到 SIGTERM 时，尝试恢复原模式。即使控制循环卡住，守护仍可运行。

接管原状态在首次手动写入前原子保存至 `data/nvidia-leases.json`。恢复成功才删除相应记录；失败会保留并重试。新的服务单元有 `ExecStopPost` 恢复钩子，下一次写入进程启动时也先恢复残留记录。恢复尚未成功时不覆盖旧租约。

软件守护依赖操作系统和 NVIDIA 驱动可用。整个进程组被 SIGKILL 时依赖 systemd 钩子或下一次启动恢复；驱动失联、系统挂死等情况无法承诺立即恢复。不要在仍有未恢复记录时删除该文件。

查看状态：

```bash
./webui.sh --diagnose
systemctl status fancontrollx --no-pager
sudo journalctl -u fancontrollx -n 50 --no-pager
```

停止服务后，可单独重试残留记录的恢复（不要与运行中的写入进程竞争）：

```bash
sudo systemctl stop fancontrollx
sudo /usr/bin/python3 -m fancontrollx.nvidia --recover --data-dir ./data
```

## 验证

`tests/test_nvidia.py` 使用模拟 NVML 和临时目录，覆盖自动/手动原状态恢复、写入前日志持久化、逐通道租约失效、父进程退出、恢复失败重试、温度保护、驱动限幅、停转设备发现、0% 曲线自动切换、共享曲线修改、温度回差及后台重启，不接触真实显卡。

本机已完成只读探测：RTX 5080、驱动 595.99.02，暴露 3 个风扇索引，调速范围 30–100%，逐路百分比/模式/RPM 查询可用。实机写入验证需要 sudo 权限；模拟测试不代替另一台机器的调速与恢复验证。

接口依据：[NVIDIA NVML 控制接口](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceCommands.html)、[NVML 查询接口](https://docs.nvidia.com/deploy/nvml-api/latest/api/group__nvmlDeviceQueries.html)。
