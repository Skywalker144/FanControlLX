# 前端约定：一致性与低资源占用

FanControlLX 使用原生 HTML/CSS/JavaScript；资源编译进 Rust 可执行文件。构建和运行不需要 npm，不使用外部 CDN、在线字体或图标服务。界面采用紧凑、中性的工具布局；没有安装 shadcn/ui，也不把相似外观称为使用了该组件库。

## 组件与依赖

- 优先复用浏览器的 `dialog`、`select`、`range`、表单、Grid/Flex、Pointer Events 和键盘行为，再考虑引入第三方库。已有依赖或原生控件能够正确表达时，不另写同类基础行为。
- 按钮、卡片、表单、状态标签使用 `static/style.css` 的颜色、字号、圆角、间距和动效变量。观看页与编辑页共用这些样式。
- 图标只使用 `static/icons.svg` 中的 Lucide 子集。来源固定为 Lucide 0.468.0，授权随 SVG 一并分发；增加图标从该版本的官方 SVG 获取，不临摹路径，不加载完整图标运行时。GPU 使用该版本的 `circuit-board` 图标。
- `static/ui.js` 共享主题和按变化写入 DOM 的辅助函数；`static/confirm.js` 使用原生 `<dialog>` 和 `method="dialog"` 表单统一确认操作。浏览器负责模态焦点和 Escape，取消按钮默认聚焦。离开网页的未保存提示继续使用浏览器的 `beforeunload`。
- `static/curve.js` 只处理共享预览与插值；`static/curve-editor.js` 只由编辑页加载。坐标轴和节点只在曲线、选择或尺寸变化时重建，实时读数只移动标记。编辑草稿与后台配置保持分离。
- 当前排序已有鼠标、触摸、键盘、取消和持久化回归。暂时保留现有实现；如果后续扩展到跨区拖放或更多排序类型，再评估 dnd-kit 与维护成本。
- 不为当前功能引入 React、Motion、Zustand 或可调整分栏。以后选型应以具体需求、按需构建体积、实测浏览器开销和维护收益为依据，不能仅因规范列出了库名就全部安装。

## 更新与动画

- 可见页面每次轮询完成后约 1.5 秒再次刷新；隐藏时停止，恢复可见时立即刷新。后台采样和硬件保护独立运行。
- 观看页只请求 `/api/view`，不加载编辑器、提交控制请求或发送设备发现心跳。
- 风扇读数变化只更新文本、输出条和 SVG 标记，保留卡片与曲线节点。相同文本、属性和静态内容不重复写入。每张卡片只保留当前结构签名，不累积历史 DOM。
- 输出条直接显示最新值，不对高频读数做宽度动画。按钮、开关和弹窗只在交互时做短暂反馈；遵守 `prefers-reduced-motion`，不持续旋转图标或启用装饰性循环动画，不使用背景模糊。

## 验证

`tests/browser-smoke.mjs` 检查观看/编辑分离、隐藏页停止轮询、读数更新时保留图表节点、编辑焦点、确认取消/提交、曲线、拖拽以及桌面/手机布局。

浏览器性能脚本不安装依赖，也不写入演示配置。只允许对演示实例运行：

```bash
./target/release/fancontrollx --demo --service --port 18091 --data-dir /tmp/fancontrollx-perf-demo
# 另一终端；输出目录需事先存在
CHROME_BIN=/path/to/chrome node tests/benchmark_frontend.mjs \
  http://127.0.0.1:18091 test-results/frontend.json
```

脚本在无头 Chromium、关闭 GPU、1440×1100 下，对观看页、控制页、新建共享曲线窗口各测约 6.5 秒。固定配置与历史，每次轮询模拟读数变化，以隔离渲染工作。记录渲染线程任务耗时、布局次数、图表 DOM 变化和 GC 后 JS 堆。它不测整个浏览器进程 RSS、真实 GPU 成本或耗电，也不能把结果直接解释为整机 CPU 降幅。DOM 观察器和测试工具本身有开销。

## 2026-10-21 前端对照记录

同一 Chromium 版本、相同初始演示配置，分别测量修改前后二进制；每场景一个约 6.5 秒窗口，均包含 4 次模拟轮询。新建共享曲线场景没有绑定风扇，图表形状和实时预览本来就不需要变化。

| 场景 | 渲染线程任务耗时：修改前 → 修改后 | 布局次数：修改前 → 修改后 |
|---|---:|---:|
| 观看页 | 16.63 → 8.38 ms | 4 → 4 |
| 编辑页 | 79.97 → 10.03 ms | 124 → 4 |
| 新建共享曲线窗口 | 79.62 → 11.95 ms | 128 → 4 |

共享曲线图表在测量窗口内的结构重建从 4 次降至 0 次。观看页的实时数值更新保留曲线节点；浏览器回归另行验证节点身份和焦点。主要收益来自消除输出条宽度动画的连续布局，以及保留图表结构。任务耗时是该窗口内的累计值，包含测试开销，不是单次点击延迟，也不是整机 CPU 使用率。单轮短时结果会受系统调度影响，不作普遍降幅保证。

完整静态源文件总和从 111,763 增至 119,656 字节（约增加 7.7 KiB），包含图标授权、共享模块、确认窗口与样式变量。观看页 JavaScript 为 9,191 字节，编辑页 JavaScript 为 58,178 字节，均为未压缩源码，不等于浏览器内存。没有增加 JavaScript 框架或第三方运行时。

Lucide 子集 SVG 含授权为 4,372 字节；本节前端对照测量时静态资源仍使用 `no-store`，同页不同阶段创建的 SVG 引用可能重复请求。后续后台审查已加入 ETag 重验证，详见 [性能审查](PERFORMANCE_AUDIT.md)。原始结果保留所有资源记录，不能把去重后的源文件总和当作实际传输量。GC 后 JS 堆在这些场景约为 0.59–0.75 MiB，只覆盖 JavaScript 堆，不覆盖 DOM、浏览器进程和 GPU 内存，不能据此宣称整页内存大幅下降。

原始数据保存在本地 `docs/performance/2026-10-21/` 的 `frontend-before.json`、`frontend-after.json` 与 `frontend-environment.json`，包含前后测量结果、源文件大小及二进制哈希。该目录由 Git 忽略，不随仓库分发；测量脚本保留在 `tests/benchmark_frontend.mjs`，后续测量输出到 `test-results/`。
