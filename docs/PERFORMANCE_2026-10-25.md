# 2026-10-25 常驻开销优化

本轮基线是开始工作时的完整工作区，包含此前尚未提交的界面和资源优化；不是 Git HEAD。使用相同的 Rust 1.99.1、锁定依赖和 release 配置构建前后版本。已有改动保留，没有新增运行时依赖、线程或定时任务。

## 实现

| 路径 | 变化 |
|---|---|
| 控制策略 | 配置加载或修改时解析数值参数、定位共享曲线；每秒控制直接使用解析结果，取消重复 JSON 参数查询与曲线库搜索 |
| 控制结果 | 保存数值结构和静态状态文本；接口请求时才生成输出 JSON，复用每路输出和控制记忆的映射条目 |
| 温度聚合 | 在栈上累计数量、总和、最小值、最大值，取消每路风扇的临时温度数组；保护判断继续使用未经平滑的最大值 |
| hwmon 采样 | 复用采样对象及静态字段，发现版本变化时重建布局；更新现有 JSON 字段时不重复分配键名 |
| 曲线库展示 | 配置对象与连接可编辑状态未变时，跳过整份曲线库的重复签名序列化 |
| 性能验证 | 增加可单独运行的控制循环和模拟 hwmon 基准，记录分配次数、累计申请字节和耗时；浏览器基准模拟真实增量配置协议 |

主板温度、RPM、模式和输出仍每轮重新打开文件并读取。缺失、无效或移除设备不使用旧读数；读数恢复后，恢复发现时记录的可写性及限制原因。重新发现会更新名称、通道顺序和设备集合。采样存储在控制异常后仍保留，供后续恢复使用。

控制周期、过热保护、停转保护、主板看门狗续期、GPU 写入进程的独立温度检查及逐路租约均保留。配置格式和 HTTP 响应字段保持兼容。共享曲线重排、编辑、风扇删除会同步更新解析后的策略。

## 控制和采样基准

三轮交替运行前后版本，报告各轮平均耗时的中位数。预热 200 次；控制循环测 10,000 次，hwmon 测 2,000 次。最终这组测量没有与本任务的构建、浏览器或黑盒验证并行执行，但没有锁定整机负载。

| 场景 | 每轮耗时：前 → 后 | 每轮分配次数：前 → 后 | 每轮申请字节：前 → 后 |
|---|---:|---:|---:|
| 3 路配置控制计算 | 7.01 → 4.79 µs | 168 → 119 | 10,244 → 7,368 |
| 64 路配置控制计算 | 108.22 → 23.67 µs | 1,152 → 119 | 61,552 → 7,368 |
| 32 个温度、8 路测速、8 路 PWM 采样 | 83.89 → 66.70 µs | 528 → 0 | 37,749 → 0 |

64 路场景计算耗时约减少 **78%**，每轮申请字节约减少 **88%**。正常 hwmon 采样在预热后无需堆分配；首次发现、拓扑变化、错误文本和 GPU 路径仍可能分配。

测量边界：

- 控制场景使用演示采样、128 条 32 节点共享曲线；只有 3 个模拟硬件通道，其余为离线风扇配置，不是 64 路真实硬件。未接管控制，平滑窗口设为 0，连续运行时不等待一秒。
- hwmon 使用临时目录中的普通文件，禁用 GPU 探测，不包含实际内核传感器驱动的读数成本。
- 计数分配器只存在于测试构建，时间包含计数开销。申请字节是累计分配流量，不是峰值内存、RSS、PSS 或 cgroup 内存。
- 演示采样仍分配模拟数据，因此 3 路和 64 路场景优化后的共同 119 次分配不代表真实 hwmon 路径。

## 演示服务与网页

`benchmark_runtime.py` 对两个 release 二进制分别执行相同的 8 秒闲置窗口和每接口 2,000 次读取，两个并发客户端。64 路配置的闲置累计服务端 CPU 为 2.51 → 0.83 ms；完整状态读取累计 CPU 为 56.66 → 46.81 ms，测试结束时 RSS 为 7.76 → 7.57 MiB。两个版本均保持 4 个线程，观测到的最大控制历史间隔约为 1.001 秒。

这些是单个短窗口，绝对差较小。接口缓存已有较好的表现，本轮主要减少没有网页访问时仍在发生的计算和分配。不能把这组演示数据当成包含 NVIDIA 驱动和独立 GPU 进程的真实服务占用。

浏览器使用同一 Chrome for Testing 148.0.7778.96、关闭 GPU、1440×1100、64 路配置和 128 条曲线；每场景约 6.5 秒、4 次模拟刷新。最终版本编辑页 GC 后 JS 堆约 2.43 MiB，基线约 2.44 MiB。任务耗时没有一致下降：观看页 35.69 → 33.76 ms，编辑页 60.14 → 62.21 ms，新建共享曲线窗口 57.60 → 69.89 ms。因此不宣称浏览器整体 CPU 或内存有稳定改善。额外保存大量 DOM 引用的试验增加了堆占用，已撤回；最终仅增加跳过重复曲线库签名的轻量判断。

二进制从 1,314,872 增至 1,331,440 字节，增加约 16.2 KiB。主要收益在运行中的控制和采样路径，不是磁盘体积。

## 验证与复现

通过 60 项 Rust 测试、21 项 Python 黑盒测试、Clippy、格式/语法检查及完整浏览器回归。新增行为覆盖包括采样存储复用后的失效/恢复/设备移除、混合温度组的聚合与保护、解析后的策略随曲线重排和删除同步更新。两个性能基准默认忽略，需要显式执行。

```bash
cargo test --locked
cargo clippy --all-targets --locked -- -D warnings
cargo test --release --locked benchmark_ -- --ignored --nocapture --test-threads=1
cargo build --release --locked
python3 -m unittest discover -s tests -p test_rust.py -v

python3 tests/benchmark_runtime.py --binary target/release/fancontrollx \
  --label after --requests 2000 --output test-results/runtime-after.json
```

对照测量需把相同基准代码放入优化前版本；基线 hwmon 基准调用原来的 `sample(false)`，优化后调用复用存储的 `sample_into`。浏览器两版使用同一更新后的测量脚本，以免把完整配置模拟响应与真实增量轮询混为一谈。

本地原始数据、工作区基线、构建哈希和日志位于 `test-results/performance-2026-10-25/`，由 Git 忽略。主要结果为 `hotpath-comparison.json`、`runtime-before.json` / `runtime-after.json`、`frontend-before.json` / `frontend-after.json` 和 `environment.json`。

本轮已生成 release 可执行文件，没有重启已安装的风扇服务。应用需重启服务并刷新网页。真实常驻 CPU/内存的变化仍需部署前后在相同配置、GPU 模式和网页数量下，用 `tests/benchmark_service.py` 对服务 cgroup 测量。正常 NVML 驱动调用和 GPU 恢复进程仍有必要成本；兼容回退 `nvidia-smi` 的同步等待仍是已知延迟限制，本轮未修改其行为。
