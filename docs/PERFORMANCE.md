# Python → Rust 性能实测

2026-10-20，在同一台机器、同一份配置下，实际控制 6 路风扇的后台服务 CPU 占用降低约 **39.7%**，服务内存降低约 **37.1%（20.45 MiB）**。控制周期没有变慢。

## 整个后台服务

测量包括主进程及独立 NVIDIA 写入进程，不包括浏览器。分别测量三个 30 秒窗口；CPU 为三个窗口的平均值，内存为所有每秒样本的中位数。

| 指标 | Python 0.5.1 | Rust 0.6.0 | 变化 |
|---|---:|---:|---:|
| CPU，占一个核心的比例 | 4.005% | 2.414% | 降低 39.7% |
| 服务 cgroup 内存 | 55.06 MiB | 34.61 MiB | 减少 20.45 MiB，降低 37.1% |
| 控制历史采样间隔，中位数 | 1.088 秒 | 1.060 秒 | 缩短 2.6% |
| 控制历史采样间隔，观测最大值 | 1.123 秒 | 1.106 秒 | 未观察到变慢 |
| 完整状态 API 延迟，中位数 | 1.427 毫秒 | 0.725 毫秒 | 缩短 49.2% |
| 完整状态 API 延迟，样本 P95 | 1.592 毫秒 | 0.805 毫秒 | 缩短 49.4% |

CPU 的 100% 表示占满一个核心，不是整机所有核心。绝对下降约 1.59 个百分点；不能把相对降幅 39.7% 解读为整台电脑的 CPU 使用率下降 39.7%。内存使用 cgroup v2 的 `memory.current`，包括该服务的相关内存计费，不等同于单进程 RSS。

| 窗口 | Python CPU | Rust CPU | Python 内存中位数 | Rust 内存中位数 |
|---|---:|---:|---:|---:|
| 1 | 3.942% | 2.441% | 55.54 MiB | 34.95 MiB |
| 2 | 4.085% | 2.359% | 54.82 MiB | 34.58 MiB |
| 3 | 3.988% | 2.441% | 55.05 MiB | 34.61 MiB |

### 条件与边界

- 机器：Intel Core Ultra 7 265K（20 个逻辑 CPU）、RTX 5080、MAG B860M MORTAR WIFI / NCT6687D，Linux `7.0.0-38-generic`。
- 原版基线：提交 `a2878927a29119e4e400e29562cd1d8362ff0558`，升级前正在运行的 Python 服务。新版使用 release 构建并由 systemd 启动。
- 两版均有 35 个温度传感器、11 个可枚举通道，启用 6 路控制，其中 3 路 NVIDIA 风扇处于显卡自动调速状态。测量前后无风扇故障。
- 配置 JSON 规范化后的 SHA-256 完全一致：`7c01a4bed01116bfb184f304b7e907b920111f32ad336cae29c4f608fc7f60f2`。没有通过停用风扇、减少已配置设备或延长实时控制周期获取降幅。
- 原版测量于 19:07:26 开始，新版于 19:22:32 开始（北京时间）。新版已运行约 2 分 45 秒；旧版已长期运行。不同进程运行时长、驱动状态、其他程序负载和系统调度可能影响结果。
- 资源窗口内测量脚本不发 HTTP 请求。API 延迟在资源窗口结束后另做 30 次连续请求，包含本机客户端开销。没有锁定整机负载或监控其他网页连接，因此这是本机短时运行对照，不是严格隔离的实验。
- 控制间隔来自最终状态中的最近历史，可能涵盖测量开始前的数据；它不是硬件中断响应时间或最坏情况延迟保证。P95 也只是这 30 次请求的样本分位数。
- 后台控制仍约每秒运行。网页隐藏时停止轮询已通过浏览器回归验证，但没有单独测量浏览器内存和耗电，不能将其计入上表。

## 只读硬件采样对照

另从原始提交导出独立目录，交替运行 Python / Rust 只读采样，每版三轮、每轮 20 次，每次后休眠 1 秒。每轮先预热；不启动控制器或改变硬件。该对照进行时，原 Python 服务继续控制实际风扇。

| 指标 | Python | Rust | 变化 |
|---|---:|---:|---:|
| 每次采样 CPU 时间，三轮均值 | 24.25 毫秒 | 19.01 毫秒 | 降低 21.6% |
| 每次采样耗时，合并样本中位数 | 40.57 毫秒 | 29.73 毫秒 | 缩短 26.7% |
| 独立采样进程 RSS，三轮中位数 | 39.12 MiB | 22.98 MiB | 降低 41.2% |

这张表只代表硬件读取路径，不能当作整个后台的节省，也不能与上一张表的降幅相加。驱动及 sysfs 读取仍有成本，换语言不会消除这些开销。

## 复现

测量当前服务（只读，需要能够读取 systemd/cgroup 及本机 API）：

```bash
python3 tests/benchmark_service.py \
  --label rust --windows 3 --seconds 30 \
  --output test-results/performance/rust-service.json
```

复现原始代码的只读采样对照：

```bash
reference_dir=$(mktemp -d /tmp/fancontrollx-reference.XXXXXX)
git archive a2878927a29119e4e400e29562cd1d8362ff0558 | tar -x -C "$reference_dir"
/usr/bin/python3 tests/benchmark_sampling.py \
  --reference "$reference_dir" --rounds 3 --samples 20 \
  --output test-results/performance/sampling-comparison.json
```

整体服务对照需要依次运行两版服务，保持配置和工作负载一致；不能同时启动两个硬件控制器。本次原版数据在升级前已采集，无需为得到基线再切回旧版。

这些数据支持本机当前配置下的资源下降和响应改善，不代表所有硬件、长期内存上限或节电瓦数。
