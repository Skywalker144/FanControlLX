# 2026-10-22 资源占用审查

本轮在已有 Rust 后台、按需设备发现、响应缓存和隐藏页停刷的基础上继续优化。主要收益来自观看页增量传输、消除编辑页每张卡片保存一份曲线库的重复，以及减少采样分配。允许大规模重构，但目前没有证据支持为了资源占用更换运行时或前端框架。

保留工作区已有界面改动。对照基线是本轮开始时的工作区构建，不是 Git HEAD，也不是历史 Python 服务。测试控制写入均使用临时演示配置或模拟 NVML；真实硬件只做只读采样。已构建可执行文件，没有重启已安装的风扇控制服务。

## 已实施

| 路径 | 变化及作用 |
|---|---|
| hwmon 每秒数值读取 | 使用 64 字节栈缓冲区，取消每个数值的文件大小查询和字符串分配；每次重新打开并读到 EOF，设备移除、替换和无效内容仍立即可见 |
| 温度聚合 | 直接求组内最大值，取消每颗风扇、每个温度组的临时数组；组内任何缺失读数仍触发保护 |
| 温度历史 | 180 条记录以数值结构保存，接口需要时才构造 JSON；满容量先淘汰旧记录再插入，避免扩容 |
| 观看页接口 | 首次获取配置及最近 80 条历史，后续只传新增历史和实时输出；静态名称、曲线和节点按版本复用 |
| 增量恢复 | 使用启动随机标识、配置哈希和采样序号；重启、配置变化、越界游标及超过历史窗口时补全，历史合并不依赖系统时钟递增 |
| 编辑页卡片 | 曲线库和来源标签的结构签名只保存一份；配置或来源变化时才重算；按 ID 索引卡片和通道 |
| 浏览器刷新 | 复用数字/时间格式器，温度趋势保留 SVG 路径节点，只更新属性 |
| GPU 写入进程 | 最后一路 NVIDIA 租约成功恢复后关闭连接、回收子进程；下次接管再启动。仍有租约或恢复失败时保留守护 |

保持约每秒控制、所有实时温度及测速读取、主板看门狗续期、GPU 每路 10 秒租约及写入进程自身温度检查。GPU 曲线为 0% 但控制开关仍启用时依然持有租约，保留独立守护，不触发空闲回收。

## 测量结果

### 观看页传输

使用 `tests/benchmark_runtime.py` 的隔离演示实例。通过演示扫描填满历史，然后测量 20 次刷新，每次之间产生两条新历史记录。记录响应体字节数，不包含 HTTP 头、连接成本或扫描成本。

| 配置 | 修改前每次响应体 | 修改后每次响应体 | 减少 |
|---|---:|---:|---:|
| 3 路默认配置、80 条历史 | 约 5.10 KB | 约 1.16 KB | 约 77% |
| 64 路离线配置、128 条曲线 | 约 37.95 KB | 约 13.69 KB | 约 64% |

KB 为十进制。首屏、配置变化和恢复补全仍传完整数据；不带参数的 `/api/view` 保留完整响应。新协议增加少量版本字段，因此完整响应略大，节省发生在持续刷新的增量请求中。

### 浏览器大配置

同一 Chrome for Testing 148.0.7778.96，无头模式、GPU 关闭、1440×1100。每场景约 6.5 秒、4 次模拟刷新；配置固定，模拟读数和 80 条温度历史变化。两版使用同一测量脚本。大配置为 64 路离线风扇、128 条 32 节点曲线，不代表 64 路真实硬件。

| 大配置场景 | 渲染线程累计任务耗时：前 → 后 | GC 后 JS 堆：前 → 后 |
|---|---:|---:|
| 观看页 | 49.99 → 43.97 ms | 1.26 → 1.26 MiB |
| 编辑页 | 117.56 → 66.93 ms | 14.71 → 2.90 MiB |
| 打开新建共享曲线窗口 | 111.51 → 69.34 ms | 14.80 → 2.96 MiB |

编辑页 JS 堆约减少 80%，主要来自去掉每张卡片重复保留的曲线库签名。任务耗时包括测试工具开销，只代表短时窗口，不是整机 CPU 百分比。普通三路配置的窗口耗时约 11–18 ms，重复测量有波动，未确认稳定的常驻 CPU 降幅。JS 堆不包括 DOM、浏览器进程及 GPU 内存；不能将上表解释为整个浏览器内存降低 80%。

### 后台采样与剩余成本

相同的 `strace -c ... --benchmark 3` 路径，包含初始化发现和三次只读采样，`statx` 从 **329 次减少到 93 次**，`read` 均为 **667 次**，`ioctl` 均为 **83 次**。这是减少查询和分配，并没有减少真实读数或驱动检查。

真实硬件另交替采样三轮，每轮 12 次。两版每次采样 CPU 时间都在约 11–18 ms 的范围波动，未锁定整机负载，期间还有开发验证任务；这些短窗口不用于承诺整个服务的 CPU 或功耗降幅。驱动 `ioctl` 在追踪中仍占大部分系统调用耗时。两个必要的 NVML 实例、驱动调用与实际硬件读取构成主要剩余成本，不能用演示进程的低 CPU/RSS 推算真实后台占用。

GPU 写入进程回收会避免停用全部 GPU 控制后继续保留一个加载驱动库的进程，但尚未对真实服务测量对应的 cgroup 内存差值，不给出固定 MiB 降幅。重新启用时要承担一次进程启动、NVML 初始化及遗留恢复记录检查。

当前不继续改动的路径：

- HTTP 的固定工作线程和有界队列在闲置时阻塞等待。改成异步运行时会增加复杂度，目前没有证据表明能获得明显收益。
- 正常 NVML 路径不启动外部查询进程。兼容回退的 `nvidia-smi` 仍同步运行，最多等 2 秒；在只使用该回退路径的机器上值得另做延迟专项测量。
- 不延长安全采样间隔，不跨周期缓存温度，不合并主进程与 GPU 恢复进程，也不长期持有 sysfs 描述符。降低实际控制频率需要新的安全设计与真实硬件验证。

## 验证与复现

通过 57 项 Rust 单元测试、21 项 Python 黑盒测试、Clippy、语法/格式检查和完整桌面/手机浏览器回归。新增覆盖包括数值过长/无效/文件替换、增量历史窗口与重启、静态曲线恢复、趋势节点复用，以及 GPU 全部恢复后的退出和再次接管。原有温度保护、停转保护、独立租约、SIGTERM/SIGKILL 恢复及保存冲突测试保留。

```bash
# 分别保存前后构建；脚本自行启动、清理临时演示实例。
python3 tests/benchmark_runtime.py --binary /path/to/before \
  --label before --output test-results/runtime-before.json
python3 tests/benchmark_runtime.py --binary target/release/fancontrollx \
  --label after --output test-results/runtime-after.json

# 只读真实硬件，不接管风扇。
target/release/fancontrollx --benchmark 12

# 浏览器性能：先按 README 启动临时演示服务。--large 会替换该演示配置。
CHROME_BIN=/path/to/chrome node tests/benchmark_frontend.mjs \
  http://127.0.0.1:18091 test-results/frontend-large.json --large
```

本轮原始 JSON、测试日志和二进制副本保存在本地 `test-results/resource-audit/`，被 Git 忽略。浏览器对照使用 `frontend-before.json`、`frontend-large-before.json` 和两个 `*-after-final.json`；运行时使用 `runtime-*-final.json`。环境与构建哈希见同目录 `environment.json`。追踪数据不用于浏览器或后台功耗推断。

构建完成后需重启服务并刷新网页才能使用新版本。要确认真实常驻资源变化，应在同样风扇配置、GPU 模式和网页连接数量下，用 `tests/benchmark_service.py` 测量部署前后的服务 cgroup。
